## OOP (Object-Oriented Programming)

Рассказывать вам об основах ООП я не буду, потому что 
это все прекрасно знаете. Лучше давайте все сравним с `C#`, 
который мы с вами так хорошо знаем. 

1. В `Python` нет модификаторов доступа, 
   все атрибуты и методы по умолчанию публичные. 
   Но есть соглашение, что если атрибут или метод начинается с `_`, 
   то он считается защищенным (protected), а если с `__`, 
   то приватным (private). 
   Однако это всего лишь соглашение, и на практике вы можете 
   получить доступ к таким атрибутам и методам извне класса.

2. В `Python` нет понятия создания класса без конструктора. 
   Конструктор в `Python` всегда определяется методом `__init__`. 
   Если вы не определите его, то будет использоваться конструктор по умолчанию, 
   который ничего не делает.

3. Для инкапсуляции в `Python` используются свойства (properties) 
   с помощью декоратора `@property`. Это позволяет контролировать доступ 
   к атрибутам класса и выполнять дополнительные действия при их чтении или записи. 

4. Перегрузка операторов в `Python` осуществляется с помощью специальных методов, 
   таких как `__add__`, `__sub__`, `__mul__` и т.д. 
   Это позволяет определять, как объекты вашего класса будут вести себя при использовании 
   стандартных операторов.

5. Перегрузка методов в `Python` не поддерживается напрямую, 
   но вы можете использовать аргументы по умолчанию или `*args` и `**kwargs`, 
   чтобы создавать методы, которые могут принимать разное количество аргументов.

6. Наследование в `Python` поддерживает множественное наследование, 
   что позволяет классу наследовать атрибуты и методы от нескольких базовых классов. 
   Однако это может привести к проблемам с разрешением имен (MRO - Method Resolution Order), 
   поэтому важно понимать, как работает MRO в `Python`. MRO работает так, что сначала ищется метод в самом классе,
    затем в его родителях слева направо, и так далее. 

7. Абстрактные классы в `Python` реализуются с помощью модуля `abc` (Abstract Base Classes).

```python

from abc import ABC, abstractmethod

class Animal(ABC):
    @abstractmethod
    def make_sound(self):
        pass

class Dog(Animal):
    def make_sound(self):
        return "Woof!"

dog = Dog()

anim = Animal()
```

8. Интерфейсы в `Python` не существуют как отдельная концепция, 
   но вы можете использовать абстрактные классы для создания интерфейсов. 
   Кроме того, в `Python` используется концепция "утиной типизации" (duck typing), 
   что означает, что если объект ведет себя как определенный тип (имеет нужные методы и атрибуты), 
   то он считается экземпляром этого типа, независимо от его фактического класса.

```python
class Bird:
    def fly(self):
        return "Flying"

class Airplane:
    def fly(self):
        return "Flying"

def make_it_fly(flyable):
    return flyable.fly()

bird = Bird()
plane = Airplane()
print(make_it_fly(bird))  # Output: Flying
print(make_it_fly(plane))  # Output: Flying
```
